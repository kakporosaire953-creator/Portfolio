L’histoire de THE KRAFTER

THE KRAFTER est né d’une conviction simple : une interface est un objet fabriqué. Elle a un auteur, des contraintes, une structure et une finition.

Le nom vient de l’artisan : celui qui connaît son matériau, qui répète le geste, qui signe son travail. Le numérique n’y échappe pas : derrière chaque écran soigné, il y a des décisions précises et beaucoup de travail invisible.

01 / Philosophie

Trois convictions

01

La structure avant le style

Une interface tient d’abord par son architecture : hiérarchie, grille, ordre de lecture. Le style vient habiller une structure qui fonctionne déjà.

02

Le mouvement doit expliquer

Une animation sert à montrer un changement d’état, une continuité, une relation. Si elle ne raconte rien, elle disparaît.

03

Le code fait partie du design

Une maquette n’existe que si elle est construite avec soin : performance, accessibilité, responsive, maintenabilité.

02 / Trajectoire

Comment j’en suis arrivé là

Chapitres thématiques : je ne publie pas de dates que je ne peux pas confirmer.
01Origine

Cotonou

Grandir au Bénin, dans un environnement où le numérique avance vite et où les outils manquent. Apprendre à faire beaucoup avec peu : c’est là que se forme le réflexe de l’essentiel.

02Apprentissage

Le code, puis le design

Le développement web comme porte d’entrée : HTML, CSS, JavaScript, puis React et Next.js. Très vite, une évidence : la qualité d’un produit se joue autant dans l’interface que dans le code.

03Pratique

Produits, hackathons, clients

Des projets étudiants, des plateformes e-commerce, un hackathon, des portfolios pour des professionnels. Chaque projet ajoute une contrainte : conversion, accessibilité, multilingue, performance.

04Aujourd’hui

THE KRAFTER

Une pratique indépendante qui réunit design et développement sous une même signature : concevoir le système, puis le construire avec précision.

03 / Approche

Design et développement, même geste

Je travaille en boucle courte : une intention de design, un prototype, un composant, un test sur appareil réel. Les allers-retours entre Figma et l’éditeur de code sont volontaires : c’est là que naissent les détails justes : un espacement, une vitesse d’animation, une couleur d’état.

  • Systèmes de design construits en même temps que les composants
  • Direction artistique typographique, pas de template
  • Animation pensée dès la maquette (GSAP, anime.js, Three.js)
  • Contrôle d’accessibilité avant livraison
